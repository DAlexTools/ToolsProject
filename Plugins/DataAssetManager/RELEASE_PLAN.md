# DataAssetManager — аудит и план релиза

Дата: 2026-09-28. Область работ: только `Plugins/DataAssetManager/**`.

## Итог аудита

Функциональная основа реализована, но готовность к релизу пока не подтверждена. До релиза необходимо исправить поведение сохранения, сканирование и жизненный цикл, унифицировать JSON-импорт, проверить самостоятельную сборку и подготовить документацию.

Это статический аудит исходников, descriptor, Build.cs и тестов. Сборка, Automation Tests, упаковка и ручная проверка UI в рамках этого аудита не запускались. Наличие реализации или теста не означает, что функция успешно прошла проверку. Базовая версия для первого цикла — UE 5.5 из `ToolsProject.uproject`; поддержка других версий и платформ не установлена.

## Что уже реализовано

- Editor-модуль, открытие через Tools, настройки проекта, вкладка и статус-бар.
- Список Data Assets, поиск по имени, фильтры по типу, плагину, изменённым и невалидным ассетам; настройка колонок.
- Создание, переименование, дублирование, перемещение, удаление, сохранение выбранных ассетов.
- Details View, множественное редактирование, Property Matrix, сброс к CDO, рандомизация числовых свойств.
- Экспорт/импорт JSON, копирование путей и ссылок, метаданные, интеграции с инструментами Asset Manager Editor.
- Валидация через `UObject::IsDataValid`, просмотр зависимостей и referencers, сравнение свойств и перенос значения между ассетами.
- Выделены `FDataAssetManagerAssetService`, `FDataAssetListModel`, утилиты путей.
- Есть тестовый модуль: функции/пути/JSON/CDO, модель фильтров, сервис операций/валидации/diff, колонки и отдельные проверки виджетов.

## Риски, требующие проверки

- SaveAsset использует прямой SavePackage: проверить read-only, source control checkout, ошибки записи и пользовательскую обратную связь.
- MoveAssets заранее вычисляет имена всей пачки и возвращает 0 при общем отказе RenameAssets. Проверить одинаковые имена из разных папок и частичный успех; не обещать атомарность без подтверждения.
- Delete из UI использует default `bShowConfirmation=false`. Проверить фактические диалоги движка, отмену, ссылки на удаляемые объекты и дать явное подтверждение пользовательского удаления.
- Валидация вызывает только IsDataValid объекта. Определить, обещает ли продукт поддержку Editor Validator Subsystem; если да — интегрировать и проверить, если нет — описать границу функции.
- Статусы validation хранятся по package name: проверить их актуальность после редактирования, rename, delete и Undo/Redo.
- Выбор типов использует короткое имя класса; проверить классы с одинаковыми именами из разных пакетов. Исключения сканирования сравнивают точный class path; определить, должны ли исключаться наследники.
- Сканирование автоматически добавляет project plugins вне настроенных директорий, engine plugins не добавляет автоматически. Закрепить ожидаемое поведение настройками и документацией.
- Проверить копирование diff для массивов, структур, ссылок и instanced subobjects, Undo/Redo и сохранение после повторного открытия редактора.
- Проверить закрытие основного окна при открытых дочерних окнах, повторное открытие, перезапуск через настройки, остановку редактора и commandlet-сценарии.

## Порядок работы

### Этап 1. Воспроизводимая самостоятельная сборка

- [ ] Зафиксировать UE 5.5 / Win64 Editor как исходную проверочную конфигурацию. Дополнительные версии и платформы включать в поддержку только после отдельных прогонов.
- [ ] Удалить использование private headers движка, объявить прямые зависимости модулей; проверить зависимости публичных заголовков, убрать дубликаты в Build.cs.
- [ ] Выполнить чистую сборку плагина в отдельном минимальном host project и упаковку через UAT BuildPlugin; дополнительно проверить non-unity сборку.
- [ ] Определить поставку DataAssetManagerTests: оставить для разработки/CI, отделить от пользовательского пакета либо документировать включение. Сейчас модуль включён в descriptor как обычный Editor-модуль.
- [ ] Добавить локальные скрипты сборки/проверок под плагином с параметром пути к UE; сохранять отчёты вне исходников.

Готово, когда: чистый host собирается без других плагинов ToolsProject, все прямые зависимости заданы, есть воспроизводимые команды и журнал успешной упаковки.

### Этап 2. Безопасные операции с данными

- [ ] DAM-01: сохранять только dirty Data Assets в определённой области менеджера; поисковые UI-фильтры не должны неявно менять смысл Save All. Добавить regression test: посторонняя карта и другой тип ассета остаются dirty.
- [ ] DAM-04: единый JSON-сервис для UI/API. Валидировать данные до изменения оригинала; при неуспехе оставлять объект неизменным. Успешный импорт — одна Undo/Redo-операция с уведомлением об изменении и dirty flag.
- [ ] Проверить malformed JSON, неверный тип поля после корректного поля, неизвестные/пропущенные поля, несовместимый класс, массивы, структуры и ссылки. Зафиксировать правила формата и совместимости.
- [ ] Проверить сохранение read-only/source-controlled пакетов; выводить конкретный результат, включая частичный успех пачки.
- [ ] Проверить коллизии имён при move/duplicate, отмену, невалидные пути и недоступные mount points; учёт результатов по каждому ассету.
- [ ] Подтверждение удаления из UI, проверка references и отмены. Не заявлять Undo файловых операций без проверки поведения UE.
- [ ] Свести операции UI к сервисам, которые действительно покрывают тесты.

Готово, когда: нет изменения посторонних пакетов; неуспешный импорт не меняет данные; ошибки и частичный успех видны пользователю; проверки сохранения и Undo/Redo проходят.

## Условия выпуска

- Закрыты DAM-01…DAM-07 и DAM-09; DAM-08/DAM-10 устранены либо оставшиеся ограничения обоснованы и документированы.
- Пройдены чистая сборка/упаковка, Automation Tests и ручная проверка установленного пакета.
- Проверены неуспех/отмена операций, JSON без частичных изменений, сохранение без посторонних пакетов и ожидаемые Undo/Redo-сценарии.
- Нет подтверждённых падений, потери данных или блокирующих ошибок в поддерживаемой конфигурации.
- Документация, версия descriptor и фактический артефакт согласованы.

Работы не требуют изменений других плагинов. Тестовые host projects и результаты запусков должны быть временными или исключёнными из поставки. Рефакторинг большого виджета выполнять только для устранения дублирования и проверяемости перечисленных сценариев; новые крупные возможности вынести за пределы первого релиза.
